
\chapter{Triển khai và kiểm thử}

\section{Kiến trúc triển khai đề xuất}
Một môi trường tối thiểu có thể gồm:
\begin{enumerate}
  \item Web client trên Chrome/Edge/Firefox.
  \item Application server chạy backend API và web application.
  \item Relational database server.
  \item UAV mobile gateway với local storage.
  \item Các sensor node phân bố theo zone.
  \item Dịch vụ email nếu notification email được bật.
\end{enumerate}

\section{Quy trình triển khai}
\begin{enumerate}
  \item Chuẩn bị server và database.
  \item Tạo schema và indexes từ DDL đã được nhóm kiểm thử.
  \item Cấu hình backend connection string và secret.
  \item Cấu hình authentication/authorization.
  \item Đăng ký farm, zone, sensor type, sensor node, UAV và gateway.
  \item Cấu hình threshold.
  \item Cài web application.
  \item Cấu hình gateway và offline storage.
  \item Thực hiện test end-to-end trước khi vận hành.
\end{enumerate}

\section{Kiểm thử hiệu năng}
Mục tiêu từ đề bài là thao tác web thông thường phản hồi khoảng 3 giây và dữ liệu mới đồng bộ xuất hiện trên dashboard khoảng 10 giây. Khi benchmark, nhóm nên tách:
\begin{itemize}
  \item latency API;
  \item thời gian ghi database;
  \item thời gian xử lý ingestion;
  \item thời gian đồng bộ batch;
  \item thời gian refresh dashboard;
  \item tỷ lệ retry/error.
\end{itemize}

\section{Bảo mật}
Các điểm tối thiểu:
\begin{itemize}
  \item Password hashing bằng thuật toán phù hợp, không lưu plaintext.
  \item HTTPS cho traffic client--server.
  \item Validation ở cả API và database.
  \item Authorization theo role.
  \item Secret/configuration nằm ngoài source code.
  \item Audit log cho thao tác quản trị và xử lý alert nếu cần.
  \item Backup database định kỳ và kiểm tra khả năng restore.
\end{itemize}

\section{Backup và khôi phục}
Backup cần được thực hiện định kỳ theo chính sách mà nhóm lựa chọn. Một backup chỉ có giá trị khi có thể restore được, vì vậy phải có test restore định kỳ. Gateway cũng phải giữ dữ liệu offline đủ lâu để vượt qua các khoảng mất kết nối dự kiến.

\section{Tiêu chí nghiệm thu}
Hệ thống được xem là sẵn sàng ở mức prototype khi các luồng chính chạy end-to-end: đăng nhập, quản lý dữ liệu nền, collection, offline/sync, mission, threshold/alert, notification và dashboard. Các chỉ tiêu NFR cần được đo bằng test thực tế thay vì chỉ ghi trong tài liệu.
